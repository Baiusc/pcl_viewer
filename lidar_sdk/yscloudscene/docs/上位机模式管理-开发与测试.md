# 上位机模式管理（2026-11-03）

## 使用

构建产物：`out/build/ninja-x64-debug/YSCloudScene.exe`。
点击设备列表中的设备，在属性面板底部使用“设备模式管理”。也可填写 HTTP 地址（支持端口）并点击查询。
选择目标后点击“执行切换”；下拉框修改不会发送写请求。模式选项取设备能力交集。
采集已连接时，切换前暂停解析并断开旧会话；确认模式后等待该模式的新发现记录和接收器停止标志，再清空组帧缓存、重新握手。
面板隐藏后停止后续 HTTP 轮询，再打开会刷新；隐藏面板不会取消设备操作。

## 实现

- `business/device_management`：协议校验、结果判断、串行 libcurl 工作线程和轮询控制。
- `component/device_management`：属性面板中的管理表单。复用浮动面板公开布局接口，不修改 lumosy。
- `mainwindow.cpp`：设备选择、采集暂停及重连协调。
- 原始点云、解算点云解析器新增管理会话缓存清理接口。
- `scene/CMakeLists.txt` 使用 `CURL::libcurl`。当前 x64-windows Debug 构建自动部署 libcurl-d.dll 和 zlibd1.dll。

HTTP 总超时 12 秒、连接超时 3 秒；不跟随重定向、不使用环境代理。保留非 2xx JSON 原因。
POST 只提交一次，202 后关联 operation_id；超时只查询，回滚和操作标识变化不报成功。
页面或地址变化通过代次丢弃旧响应。无效地址会清除原管理目标，防止误写旧设备。

## 验收边界

本轮确认管理客户端和 HTTP 模式切换。主界面的视觉效果、SDK 重连后的原始/解算点云显示、长时间采集和正在录制时的行为尚未实机验收。
采集重连等待新发现信息；设备不可发现或未重新广播目标模式时不会使用旧模式强行握手。
当前管理界面不将 pipeline_verified 当作上位机数据接收正常，也不提供未经验证的数据接收成功提示。
设备 RAM 部署重启后消失，程序不会替代设备部署或调用旧切换脚本。
