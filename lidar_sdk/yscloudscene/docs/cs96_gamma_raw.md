# CS96 Gamma 原始点云保存

连接 CS 系列设备并使用原始点云模式（`work_mode=1`）后，使用已有的“保存原始点云”入口，
选择帧数、镜面与文件名前缀。文件仍保存在程序所在目录的 `origin_cloud/<前缀_时间>/` 下。
镜面选项 0 表示所有面，1～4 对应 SLOT 0 中 `fpga_frame_id % 4` 的 0～3；不使用 ARM 帧号推导面号。

每帧生成两个同名文件：

- `.txt`：`cols: 800  rows: 120`，按槽号 0～799 输出；每槽按 FPGA 上传顺序输出像素 0～119。
  `pixel_number` 后六列依次为 `ft0 et0 pk0 ft1 et1 pk1`，全部为无符号十进制原始码值。
  像素编号固定宽度 3，各码值列固定宽度 18、右对齐；每个槽位重复列名，便于逐列对照。
  槽头同时输出原始转镜编码值、24 位相对时间（µs）、FPGA 帧号与面号。
- `.bin`：800 个 1936 字节的完整 SLOT 按槽号连接，共 **1,548,800 字节**。
  第 `s` 槽位于文件偏移 `s * 1936`；包含 16 字节槽头及保留位，不含 9 字节 UDP 外层头。
  可直接与对应 UDP 包 `value`（偏移 9 起 1936 字节）逐字节比较。

不转换距离或脉宽、不反转或重排槽内像素、不补第三回波、不清零或剔除空值、0、16 或其他无效码。

## 协议与组帧

仅识别配置连接设备 IP 发来的 1945 字节载荷，要求 CS 机型、原始点云工作模式、`sof=0xAA`、
小端 `data_len=1936`，且 UDP 槽号在 0～799 内并与 SLOT 第一个 uint32 的低 12 位相同。
同包 `seq_num` 为驱动批次下标，不参与寻址、切片、组帧或完整性判断。

按小端 16 位 ARM `frame_id` 组帧，支持 65535→0 回绕。槽位乱序时按槽号放入帧缓存，重复槽采用首次数据，
收齐 800 个不同槽才交给保存线程；缺槽的帧不导出，避免把缺失数据伪装成零值。
最多保留连续 4 个帧号内的不完整帧，连接或断开时清空 Gamma 缓存；完整帧队列最多 4 帧，
队列溢出丢弃最旧帧并记录日志。选择特定面时，只有匹配的完整帧消耗保存帧数。

解析完全独立于 1578/3138 字节真实点云和 Beta 的 96 像素布局。
操作系统完成 IPv4 分片重组，现有 IOCP 接收缓冲为 65536 字节，可完整接收 1945 字节载荷。
本功能不读取抓包文件；若从抓包重放，发送方应先重组 IP 分片。

## 验证

`Cs96GammaRawTest` 覆盖协议校验、机型/模式/IP 限制、乱序、重复与缺槽、帧号及相对时间回绕、
会话重置、120×800 全量两回波码值与 BIN 逐字节一致性，以及本机 UDP 接收至已有保存入口的全链路。

```sh
cmake --build out/build/ninja-x64-debug --target cs96_gamma_raw_test YSCloudScene
ctest --test-dir out/build/ninja-x64-debug -R Cs96GammaRawTest --output-on-failure
```
