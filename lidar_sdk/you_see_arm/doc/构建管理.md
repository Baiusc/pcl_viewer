# 构建与发布管理

## 本阶段范围

Beta/Gamma 按机型构建，每个机型只包含一份完整应用和一份运行时选择数据布局的用户态驱动。Alpha、FL6031、FL6532 暂时沿用原有按模式预设，后续逐平台迁移。

这次交付的是应用层开发包，不是完整板级固件。没有自动切换内核模块、烧写 FPGA、部署设备或接入网页。软件支持列表不代表设备已经验证可切换。

## 构建与运行

要求 CMake 3.21 以上、Ninja、Python 3.9 以上及对应交叉工具链。签名和验签另需 OpenSSL，当前使用 SHA256 配合 RSA 或 ECDSA 密钥。

```bash
python3 scripts/build.py list
python3 scripts/build.py build beta
python3 scripts/build.py build gamma
cmake --preset beta-debug
cmake --build --preset beta-debug
make PRESET=beta
```

Beta/Gamma 不再接受 `DATA_MODE`，旧的 `beta-pointcloud`、`beta-gray`、`gamma-pointcloud` 等预设已移除。构建目录为 `build/beta`、`build/gamma`，旧目录不会删除或复用。Debug 追加 `-debug`。

启动时从现有 `ys_conf.ini` 读取工作模式，修改配置后必须停止应用再重新启动；本阶段不提供进程内热切换。

| work_mode | 功能 | Beta 驱动格式 | Gamma 驱动格式 |
|---|---|---|---|
| 0 | 连续原始直方图 | `MODE_HIS` (4) | `MODE_HIS_SL100` (5) |
| 1 / 2 | 原始 / 解算点云 | `MODE_PCL` (0) | `MODE_PCL_SL100` (1) |
| 3 | 灰度 | `MODE_GRY` (3) | `MODE_GRY_SL100` (2) |

默认工作模式为 2。应用启动时调用 `lidar_api_init_mode()` 打开设备、校验 AM6204 共享参数，再由 `lidar_switch_mode()` 配置 DMA。驱动按两个单次传输缓冲区交替读写。Beta 和 Gamma 都从同一份源码构建 `liblidar.so`，各自的应用包只安装一份库。

使用统一内核驱动时，应用与动态库应成对更新。跨接收布局切换前应停止 FPGA 输出、等待 DMA 排空，并使 FPGA 按目标模式输出。`work_mode` 负责选择应用数据链路和内核 DMA 接收参数，FPGA 输出格式由板级配套负责。

## 算法

Beta 编入反射率和 SpotSlope，Gamma 编入反射率。算法缺失时构建失败，不发布缩水包。运行配置中的两个开关默认关闭，以保留原普通预设的行为：

```ini
[system]
work_mode = "2"
enable_reflectivity = "0"
enable_spot_slope = "0"
```

启用算法还需要相应标定表。原始数据透传不应用点云修正。当前开关在进程初始化时读取，修改后需要重启应用。

## 驱动与工具链来源

关系表为 `configs/build_catalog.json`。Beta/Gamma 默认使用当前 `driver/`。可通过 `YS_DRIVER_SOURCE_DIR` 显式指定提供 `lidar_receive_mode.h` 和统一接收接口的 AM6204 驱动源码。

其他机型仍可先执行 `python3 scripts/build.py prepare MF150-fl6031`，准备对应独立驱动与工具链。工具链默认优先使用已有 `build/toolchains/<前缀>`，否则使用 `cc/`。CMake 缓存选定路径，变更时要显式覆盖，切换编译器时使用新构建目录。

## 打包、签名与验证

Beta 构建同时生成独立电机初始化程序 `build/beta/platform/bin/demo_i2c_motor`，源码位于 [platform/beta/motor](../platform/beta/motor/README.md)。它通过 `lidar_platform` 安装组件进入系统镜像，不进入下述应用升级包；完整镜像整理工具默认使用本次编译产物。

```bash
# 默认未签名开发包，输出目录必须不存在，避免混入旧文件
python3 scripts/build.py package beta
python3 scripts/build.py package gamma --output /tmp/gamma-package

# 使用受控环境提供的包外私钥，不自动创建发布密钥
python3 scripts/build.py package beta --output /tmp/beta-signed \
  --sign-key /受控目录/release-private.pem

# 正式发布要求准确位于 vX.Y.Z 标签、参与构建的源码及依赖干净、来源可追溯
python3 scripts/build.py package beta --output /tmp/beta-release \
  --release --sign-key /受控目录/release-private.pem

# 使用事先信任的包外公钥验证，不能使用包中自带的公钥建立信任
python3 scripts/release_manifest.py /tmp/beta-signed \
  --public-key /可信目录/release-public.pem
```

私钥、生产信任公钥的配置及轮换应在发布环境和设备管理阶段实施。验证工具目前运行在具备 Python/OpenSSL 的开发主机；没有假设设备安装了 Python，板端 C/C++ 验签属于管理服务阶段。

```text
bin/you_see
lib/liblidar.so
conf/ys_conf.ini
manifest.json
manifest.sig                 # 提供签名密钥时生成
```

`build/<预设>/manifest.json` 是构建来源记录；`package` 命令在临时目录完成安装后，重新生成最终文件清单并可选签名，再交付整个目录。清单使用包内相对路径，覆盖全部载荷文件；验证会拒绝清单改动、载荷改动、额外文件、符号链接及错误公钥。清单记录包含的模式、格式编号、算法、驱动 ABI 和源码来源，硬件验证状态明确标为待验证。

数字签名用于检测未经授权的修改，不等于安全启动或防降级。设备受信任公钥、验证程序及启动链的保护仍需后续设计。

不会打包设备独有标定表、编码器表、SN 或现有网络参数，不执行覆盖安装。应用相对库路径为 `$ORIGIN/../lib`，必须连同驱动库交付。

## 验证

```bash
python3 scripts/build.py generate --check
python3 scripts/test_build_config.py
python3 scripts/test_runtime_driver.py
python3 scripts/test_release_manifest.py
python3 scripts/test_beta_horizontal_pipeline.py
python3 scripts/test_beta_spot_slope.py
python3 scripts/test_gamma_pointcloud_decode.py
python3 scripts/test_gamma_raw_pointcloud.py
```

构建配置测试覆盖 Beta/Gamma 的工作模式映射和完整算法。驱动测试在主机编译真实实现，用内存模拟六种 DMA 布局，验证双缓冲回绕、批次复制、旧内核拒绝、失败清理和旧 profile 接口的兼容映射。

交叉编译和上述测试通过，只能证明软件实现和打包路径可用。板端仍要逐模式验证 FPGA/内核配套、数据内容、采集速率与重复启停，之后才能将能力标记为已验证并接入自动切换事务。

## 第二阶段设备管理入口

Beta/Gamma 包新增 `bin/lidar_mgrd` 和 `bin/lidar_mgrctl`，共同纳入最终文件清单。应用新增独立运行配置、SIGTERM 退出与私有健康通知。服务协议、状态机、平台适配约束及实机验证边界见 [设备管理说明](../manager/README.md)。本阶段不修改真实设备开机项，不提供升级或冷重启接口。
