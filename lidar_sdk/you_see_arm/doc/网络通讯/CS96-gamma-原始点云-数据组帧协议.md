# CS96-gamma 原始点云数据组帧协议（UDP）

适用本次修改后的 CS96-gamma 固件，SL100 SPAD，每 SLOT 120 像素。

## 1. 启用方式与透传边界

使用 `gamma` 构建，运行时选择 `MODE_PCL_SL100` (1)，与 FPGA 点云上传格式配套。构建命令：

```bash
python3 scripts/build.py build gamma
```

部署该构建包的程序和驱动库，将板端实际使用的 `ys_conf.ini` 中 `[system]` 的 `work_mode` 改为 `"1"` 后重启程序。该构建默认生成 `work_mode="2"`。

沿用现有发现、握手、心跳、启动扫描流程。UDP 发送到握手指定的数据端口，配置默认 `center_data_port=50027`。原始模式与真实点云模式互斥；恢复真实点云使用 `work_mode="2"`。

握手端口选择遵循现有实现：优先使用 `cloud_data_port`，仅当其为 0 时才使用 `org_data_port`，与工作模式无关。抓取工具监听端口必须与最终选中的端口一致。

数据路径：`FPGA DDR → 驱动 lidar_get_bufaddr() → 生产者复制 SLOT → 消费者 → UDP`。

每个驱动 SLOT 原样保留 1936 字节，加上 ARM 生成的 9 字节包头后发送。**不倒序像素、不按 `side_light` 过滤面、不筛选回波、不做距离/反射率/坐标解算**。原始 SLOT 内的时间戳、FPGA 帧号、保留位均不改写，原始模式包长不随 `echo_mode`、`echo_type`、`coordinate_mode` 改变。FPGA 实际未上传的数据无法由 ARM 补出。

本功能用于验证应用收到的数据；不能单凭网络包证明 FPGA 到 DDR/驱动之前没有出错。需与 FPGA 对同一批数据的记录逐字节比对。

## 2. UDP 载荷：1945 字节

一个 SLOT 对应一个 UDP 数据报；无应用层切片、尾部校验码或压缩。结构体按 1 字节对齐，多字节整数采用小端序。

| UDP 载荷偏移 | 长度 | 字段 | 含义 |
|---|---|---|---|
| 0 | 1 | `sof` | 固定 `0xAA` |
| 1 | 2 | `frame_id` | ARM 计数；每次读到槽号 0 时自增，65535 后回绕 |
| 3 | 2 | `slot_number` | 从原始头低 12 位提取的槽号 |
| 5 | 2 | `seq_num` | 当前驱动批次内的 SLOT 下标，通常 0~9；不是切片号 |
| 7 | 2 | `data_len` | 固定 1936（`0x0790`，字节 `90 07`） |
| 9 | 1936 | `value` | 完整 FPGA 原始 SLOT，直接保存用于比对 |

包长公式：`9 + 16 + 120 × 16 = 1945`。包长识别需结合机型及 `work_mode=1`；不能将其交给 1578/3138 字节的真实点云解析器。

1945 字节载荷超过常见 1500 字节 MTU，会发生 IPv4 分片。上位机 UDP socket 读到的是重组后的完整载荷，接收缓冲应至少 1945 字节。使用抓包文件时需先重组 IP 分片，再按本协议解析。丢失任一 IP 分片会导致整个 UDP 包缺失。

## 3. 原始 SLOT：1936 字节

下表偏移均相对于 `value`（即 UDP 偏移 9）。

| SLOT 偏移 | 长度 | 字段 | 解析 |
|---|---|---|---|
| 0 | 4 | 槽号与转镜编码值 | 小端 uint32：`slot = word & 0xFFF`，`mirror_angle = word >> 12` |
| 4 | 3 | 相对时间 | 小端 uint24，单位 µs，24 位回绕 |
| 7 | 7 | 保留 | 原样保存 |
| 14 | 1 | `fpga_frame_id` | FPGA 帧号，0~255 回绕；当前解码器按 `% 4` 取得面号 |
| 15 | 1 | 保留 | 原样保存 |
| 16 + i×16 | 16 | 像素 i | i=0~119，保持 FPGA 上传顺序 |

每个像素包含两个连续的 8 字节回波。相对像素起点的偏移为 `echo_index × 8`，`echo_index=0,1`：

| 回波内偏移 | 长度 | 字段 | 解析 |
|---|---|---|---|
| 0 | 3 | `ft` | 前沿 TOF，小端 uint24；[23:20] 保留，[19:6] 整数，[5:0] 小数，单位 ns |
| 3 | 3 | `et` | 后沿 TOF，小端 uint24；[23:20] 保留，[19:6] 整数，[5:0] 小数，单位 ns |
| 6 | 2 | `pk` | 峰值，小端 uint16 |

以上采用修正后的 Gamma FPGA 格式。每个 TOF 的时间为 `(原始码值 & 0xFFFFF) / 64.0` ns；每个像素依次为 ECHO1 前沿、后沿、峰值及 ECHO2 前沿、后沿、峰值。峰值为完整 16 位无符号整数。

原始模式及 `parse_pixel()` 返回的 `ft/et` 仍为完整 24 位原始码值，保存时不得转换或清除保留位，不得把 `et` 改写成脉宽，不得剔除无效值或空回波。真实点云解码时才屏蔽保留位，并按 `距离(m) = 299792458 × 1e-9 × TOF(ns) / 2` 换算，随后应用距离系数和零位偏移。

与 Beta 的关键区别：Beta 现有原始点云通道会倒序像素，并按面使能过滤；本版 Gamma 保留驱动字节顺序且不做该过滤。旧版 Gamma 沿用了 Beta 的倒序路径，抓取记录时必须注明程序版本。

## 4. 上位机解析与保存

解析示例（完整接收工具见 `scripts/gamma_raw_pointcloud.py`）：

```python
from scripts.gamma_raw_pointcloud import parse_packet, parse_pixel

metadata, raw_slot = parse_packet(udp_payload)
echo1, echo2 = parse_pixel(raw_slot, 0)
# 将 raw_slot 的全部 1936 字节写入二进制文件，不做重排或数值转换。
```

建议同时保存完整 UDP 载荷和去掉外层头的原始 SLOT：

```bash
python3 scripts/gamma_raw_pointcloud.py /tmp/gamma_capture --port 50027 --source 192.168.110.10 --count 8000
```

将 `--source` 改为实际雷达 IP；去掉 `--count` 则持续保存到 Ctrl+C。输出目录必须尚不存在，避免覆盖旧记录。

工具仅接收数据，不实现握手和心跳。现有上位机需将握手的数据端口设为此工具监听端口，并持续维持心跳；若上位机已占用 50027，可给工具指定其他端口，并相应修改握手端口。工具应运行在握手指定的上位机 IP 上。

输出文件：

- `packets.bin`：按到达顺序连续保存完整载荷，每条 1945 字节。
- `slots.bin`：相同顺序保存原始 SLOT，每条 1936 字节，可用于本项目 Gamma 本地文件回放。
- `index.csv`：从 0 开始的记录下标、ARM 帧号/槽号/批次序号，以及原始槽号、转镜编码值、相对时间、FPGA 帧号。第 n 条记录在两个二进制文件中的偏移分别为 `n×1945`、`n×1936`。

保存顺序必须保持接收顺序；不要补零、去重或覆盖重复槽号。原始头与外层槽号不一致也应保留并标记，以便排查 DDR 被覆盖等问题。

## 5. 与 FPGA 比对及完整性判断

10Hz 时通常每面 800 个 SLOT，20Hz 时通常 400 个，以设备配置为准。外层头没有 `total_slots`。使用 ARM `frame_id`、槽号与原始 `fpga_frame_id`、时间、转镜编码共同对齐采集区间；不要仅以会回绕的 FPGA 帧号作为长期唯一键。

先检查槽号缺失、重复和乱序，再按相同采集区间逐 SLOT 比对完整 1936 字节。若两边都已经按相同顺序导出为纯 SLOT 文件，可以使用：

```bash
cmp fpga_slots.bin /tmp/gamma_capture/slots.bin
```

一次差异应报告记录下标、SLOT 内字节偏移及两边原始值。保留完整 16 字节头，才能区分帧对齐错误和像素数据错误。若 FPGA 导出还含 DMA 外层封装，需先按 FPGA 格式剥离成相同 SLOT 结构再比较。

透传不保证端到端无丢包：当前生产者内存池满后会丢弃 SLOT，DDR 环形区也可能被覆盖，网络 UDP 也可能丢包/乱序。应把缺包单独记录，不能直接据此认定像素字节被 ARM 修改。该功能已可通过合成数据验证消费路径逐字节一致，FPGA/DDR/实机网络端到端一致性仍需实机采集确认。
