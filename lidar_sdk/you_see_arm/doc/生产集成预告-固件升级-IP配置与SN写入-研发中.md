## 二、固件升级计划

目标是后续通过网页或上位机更新应用，减少重新烧录整个 Linux 系统的次数。

- 基础系统继续由系统镜像提供，包括启动、验签及恢复所需的稳定入口。
- `you_see`、`lidar_mgrd`、统一驱动库及配套业务 Web 等，按机型组成完整签名应用包，安装在第三分区的版本目录中。
- 升级时检查机型、兼容性、签名、文件完整性和剩余空间；安装新版本后受控重启相关服务，通过健康确认后提交，失败则恢复旧版本。
- SN、本机标定、网络配置和用户参数独立保存，日常应用升级应保留这些数据。

这里的在线更新允许采集服务短暂中断，不承诺采集不中断升级。系统、内核配套 `.ko` 和 FPGA 如需变更，应另行提供对应发布与验证流程，不能直接套用普通应用升级。

**目前在线升级入口及异常恢复闭环尚未交付。** 首次烧录的 `user.jffs2` 是第三分区初始化镜像，不能作为日常升级包覆盖正在使用的整个分区。新测试包中的旧擦写 CGI 已禁用，请勿自行恢复旧覆盖流程来替代新升级功能。

正式包格式、升级接口、失败码和具体操作步骤，以研发后续交付为准。

## 三、设备 IP 与发现计划

计划提供两种配置方式：

| 方式 | 目标行为 |
| --- | --- |
| 自动配置 | 采用 IPv4 Link-Local，在同一链路中自动获得可用的 `169.254.x.x` 地址，方便电脑直连或同一局域网接入 |
| 手动配置 | 通过受控管理入口设置 IP、掩码及需要时的网关，保存后重启仍保留 |

Link-Local、mDNS 和设备身份的分工如下：

- **Link-Local 负责地址配置。** 需要按标准进行 ARP 探测、冲突检测和处理。即使根据 SN 或 MAC 生成候选地址，也不能省略冲突检测，不能仅凭计算结果保证地址唯一。IPv4 Link-Local 用于同一链路通信，不作为跨路由访问地址。[RFC 3927](https://www.rfc-editor.org/rfc/rfc3927.html)
- **mDNS 负责本地名称解析。** 例如把设备名称解析到当前地址，不负责生成 IP。名称可考虑由真实 SN 派生，如 `yousee-<sn>.local`；此处仅为命名示例，正式命名及重名处理规则待定。[RFC 6762](https://www.rfc-editor.org/rfc/rfc6762.html)
- **服务发现可结合 DNS-SD。** 供上位机发现设备管理服务及连接端口；服务类型、字段和端口尚未冻结。[RFC 6763](https://www.rfc-editor.org/rfc/rfc6763.html)

设备的稳定身份以 SN 为依据，不以 IP 为依据。IP 改变后，上位机应能重新发现并连接同一台设备。网络设置单独持久化，不能随业务应用包更新而丢失。

手动 IP 生效可能中断当前连接，因此还需完成重新发现、误配置恢复、重启保留、多机冲突、拔插网线，以及实际使用的上位机系统兼容性测试。具体切换和恢复策略暂不作为生产承诺。

现有采集广播与握手协议先考虑兼容保留，再统一使用真实 SN。mDNS 作为独立的名称解析与发现能力接入，不要求生产同事现在迁移上位机协议。

## 四、SN 写入与身份管理计划

SN 是每台设备的出厂身份，计划写入第四分区，正常运行后只读取；应用升级、模式切换和普通恢复设置均不得改写。

当前需要特别说明：

- Beta 现有第四分区为 `sn`，Linux 节点是 `/dev/mtd3`，大小 64 KiB；其他机型最终布局需分别核对。
- 当前驱动接口按 18 字节读写 SN。`SN_set()` 每次调用都会先擦除这 64 KiB 分区，**现有接口并没有实现“写入一次后禁止修改”**，不能直接作为生产写码工具使用。
- 当前采集广播仍存在编译在程序中的固定 SN。完成第四分区写入后，还必须接通管理查询、广播和发现服务的统一身份读取，不能把固定广播字符串当作已验证的设备身份。

计划的生产写入过程为：分配本机 SN → 校验格式与唯一性 → 检查设备写入状态 → 受控写入 → 回读比对 → 重启再读取确认 → 记录结果并放行。

编码规则、存储格式、写入权限、重复写入拒绝规则，以及未写入、内容损坏和写入中断时的处理，仍需研发实现并验收。“只写一次”需要软件流程和保护共同保证，当前不等同于硬件不可改写。

正式工具交付前，请勿批量调用现有写入函数，也不要将一台设备的 SN 分区复制给其他设备。
