# 开发板 30：新镜像自动验收基线

本工具在电脑上自动驱动开发板进行测试，不把验收步骤加入正式 `you_see`。使用新镜像已经安装的 boot、crypto、service、runit、Web 和 CGI；管理程序从板上当前签名版本取得副本，仅采集程序与硬件适配使用独立模拟替身。

## 分工

| 部分 | 职责 |
| --- | --- |
| 电脑端 `run_devboard_baseline.py` | 发请求、等待最终状态、注入测试故障、判定结果，保存报告 |
| 板上已安装程序 | 正常执行验签、模式切换、状态保存、服务监督和私有健康通知 |
| 独立模拟采集 | 明确标记 DEVBOARD-MOCK；不访问雷达、FPGA、电机或 DMA |
| 人工操作 | 整机重启由人员执行，之后电脑端继续检查；本工具不自行重启或断电 |

`COMMITTED` 在本环境只证明模拟健康通知与控制流程通过，不代表真实雷达数据通过。判定同时检查 model、phase、实际及确认模式、采集 PID、初始化、管线验证和 error，不能只看 HTTP 200 或 boot ready。

## 隔离范围

- 仅允许目标 10.42.0.30；严格检查 SSH 主机密钥，密钥变化时停止并等待人工核对。
- Flash 测试数据：`/mnt/mtdblock2/lidar-acceptance/run-...`。
- RAM 运行文件：`/run/lidar-acceptance-run-...`。
- 测试 HTTP 默认 8081，已有 80 和 SWUpdate 8080 保持不变；端口占用时拒绝启动。
- 在已有 runsvdir 中增加一个明确命名的验收子树，不修改 inittab、系统配置或原 Beta 服务。
- 结束时比对原 Beta 状态文件、配置、current 链接及服务 PID，保留其原 FAULT。
- 模拟签名私钥只在电脑临时目录生成，签名后删除；只向板上传公钥和签名包。报告不保存密码。

## 运行服务级自动验收

在本项目根目录执行，使用 Python 3.9 或更新版本。首次连接或设备主机密钥变化时，先按既有流程核对并信任设备公钥；脚本不会自动删除 known_hosts。

```bash
read -rsp '开发板 SSH 密码：' LIDAR_TEST_SSH_PASSWORD
export LIDAR_TEST_SSH_PASSWORD
python3 scripts/run_devboard_baseline.py run \
  --output build/30-baseline-本次唯一名称
unset LIDAR_TEST_SSH_PASSWORD
```

输出目录需要是新目录。也可以使用已经配置的 SSH 密钥认证，不提供密码环境变量。

自动执行以下用例：模拟采集启动、2→1→2、非法模式拒绝、切换互斥、验证超时回退、故障解除后切换、正常停机保持 down、重启管理服务恢复 Flash 模式、管理进程崩溃后恢复、损坏测试包拒绝及熔断、恢复签名包后启动、原部署保护检查。

结果保存为 `报告.md`、`report.json`、`receipt.json`、`events.jsonl`。实际失败会报告 FAIL，不会改写程序状态来伪造通过。正常结束保留模拟模式 1，供人工查看及跨重启验证。

板上人工入口的实际路径记录在 receipt 中，也会显示在报告末尾。例如：

```sh
sh /run/实际验收目录/control.sh status
sh /run/实际验收目录/control.sh switch 2
```

若准备验证重启，先保持报告中的检查点状态，不再手动修改模式。

## 人工重启后继续检查

先保存服务级报告并确认没有其他升级操作。由人员正常重启开发板，再核对新的 SSH 公钥（若发生变化），之后执行：

```bash
python3 scripts/run_devboard_baseline.py resume \
  --output build/30-baseline-同一结果目录
```

仍需相同的 SSH 认证方式。恢复阶段首先检查 Linux boot_id 已改变、Flash 状态文件与重启前一致，再重建 RAM 测试入口，并检查管理程序恢复模拟模式 1。输出 `reboot-report.json`。

这验证的是“测试数据跨整机重启保留，以及手动恢复后的状态加载”。验收实例本身不是预装系统服务，因此不能把它记为该实例开机自动启动通过。生产镜像自带管理服务的自动启动另行观察记录。异常断电测试不属于本命令范围。

## 停止验收实例

```bash
python3 scripts/run_devboard_baseline.py cleanup \
  --output build/30-baseline-同一结果目录
```

只停止对应验收实例、移除对应 RAM 监督入口，保留 Flash 测试数据与本机报告。运行目录因重启消失时，先执行 resume 再清理。不要使用 killall，也不要清除 `/mnt/mtdblock2/lidar/state`。

本轮不包含真实采集、OTA 安装、SN 写入、IP/mDNS 配置、PTP 或 SSH 主机密钥持久化的验收。未执行的重启与断电项目明确记为待验证。
