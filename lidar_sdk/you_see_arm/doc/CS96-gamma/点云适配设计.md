# CS96-gamma（SL100）点云适配设计

> 版本：v2（已按 2026-10-09 讨论结论修订）
> 范围：gamma 模式「原始点云 / 真实点云」链路，直方图与灰度模式另行规划

## 1. 背景与目标

CS96-gamma 是 CS96-beta 的硬件变体：**SPAD 由 IMX459 更换为 SL100**。SPAD 更换带来两个层面的变化：

1. **驱动数据通道变化**：FPGA 上传的原始数据格式与吞吐不同，驱动的接收模式需从 `pointCloud` 切到 `pointCloud_sl100`。
2. **数据格式变化**：每 SLOT 像素数由 96 变为 120，SLOT 头的时间字段由 10 字节变为 24 位。

目标：在不影响现有 4 个机型的前提下，新增 `CS96-gamma` 机型，打通「原始点云 → 点云解析 → 网络发送」全链路。

已确认的三项决策（2026-10-09）：

| 决策项 | 结论 |
|---|---|
| 应用层代码组织 | **独立机型文件**（`*_cs96_gamma.c`），与现有 4 机型约定一致 |
| 驱动库来源 | **主仓构建时编译**（`driver` 子模块源码 + `DEF_RCV_MODE=3`） |
| SPAD 上电初始化 | **不需要 ARM 端参与**（由 FPGA 自动完成） |

## 2. 差异分析

### 2.1 驱动接收模式

`driver/src/yousee_lidar_api.h` 中 `DEF_RCV_MODE` 定义了 6 种接收模式：

| 模式 | 名称 | SPAD | 雷达 | 单 SLOT 字节数 |
|---|---|---|---|---|
| 0 | histogram | IMX459 | beta | 98312（一次性） |
| 1 | pointCloud | IMX459 | beta | **1552** |
| 2 | histogram_sl100 | SL100 | **gamma** | 122912（一次性） |
| 3 | pointCloud_sl100 | SL100 | **gamma** | **1936** |
| 4 | gray_sl100 | SL100 | **gamma** | 968 |
| 5 | gray | IMX459 | beta | 2312 |

该宏只影响 `lidar_get_bufaddr()` 的指针步进与回绕常量，即用户态读取 DDR 环形缓冲区的粒度。**gamma 点云对应模式 3**。

约束：同一份驱动源码在同一时刻只能编出一种模式；模式必须与设备上的 FPGA 固件匹配。模式通过编译期宏 `-DDEF_RCV_MODE=` 注入。

### 2.2 数据格式对比

**SLOT 头（16 字节）**

| 字段 | 位域 | beta | gamma |
|---|---|---|---|
| SLOT 序号 | `[11:0]` | `header[0..1] & 0x0FFF` | **相同** |
| 转镜角度值 | `[31:12]` | `(u32>>12) & 0xFFFFF` | **相同** |
| 时间字段 | beta `[111:32]` / gamma `[55:32]` | 10 字节原始时间戳 | **24 位 µs 相对时间** |
| 保留 | `[111:56]` | — | 7 字节保留 |
| 帧 id | `[119:112]` | `header[14]` | **相同** |
| 保留 | `[127:120]` | `header[15]` | **相同** |

**pixel（16 字节）**：ECHO1 前沿 `[23:0]` + ECHO1 后沿 `[47:24]` + ECHO1 峰值 `[63:48]` + ECHO2 前沿 `[87:64]` + ECHO2 后沿 `[111:88]` + ECHO2 峰值 `[127:112]`。

与现有 `echo_data_t`（`ft[3] + et[3] + pk[2]`）和 `point_cloud_pixel_data_t`（`echo_data_t[2]`）**逐位一致，无需改动**。

### 2.3 代码差异面（关键结论）

绝大部分差异被数据驱动掉了：

| 维度 | 处理方式 |
|---|---|
| 每 SLOT 1936 字节 | `ys_core_system.c:64` 的 `16 + lines_v*16` 由标定文件 `lines_v=120` **自动推导**，零代码改动 |
| 每帧 800 SLOT | `lines_h=800`，与 beta 相同，零改动 |
| 转镜 4 面 / 240 刻度 / PA 编码器 | 与 beta 同机制，`decode_init_model_encoder` 可原样复用 |
| 标定寄存器（0x2020/0x2030/0x2040~4C） | 文档地址与驱动 `calib_flat*_offset_set` / `calib_light_enb*` 完全对应，零改动 |
| 版本寄存器（0x3000~0x3010） | 驱动 `lidar_version_get()` 已封装，零改动 |

**真正需要写代码的只有两处**：SLOT 头时间字段解析、机型注册与文件新增。

## 4. 构建系统设计

### 4.1 机型注册（3 处必须同步）

**① `Makefile`** — 机型配置表追加一行，并新增第 6 列「驱动通道模式」：

```makefile
# 机型配置表: MODEL:编译宏:工具链前缀:driver分支:原文件名后缀:驱动通道模式
MODEL_CONFIG_MAP := \
	CS96-alpha:CS96_ALPHA:aarch64-buildroot-linux-gnu:xczu3eg:cs96_alpha:1 \
	CS96-beta:CS96_BETA:aarch64-buildroot-linux-gnu:am6204:cs96_beta:1 \
	CS96-gamma:CS96_GAMMA:aarch64-buildroot-linux-gnu:am6204:cs96_gamma:3 \
	MF150-fl6031:MF150_FL6031:aarch64-linux-gnu:t507:mf150_fl6031:0 \
	MF150-fl6532:MF150_FL6532:aarch64-linux-gnu:rv1126b:mf150_fl6532:0
```

`VALID_MODELS` 与 `help` 文案同步更新。第 6 列为 `0` 表示不使用该驱动通道（MF150 走 fs_sdk）。

**② `CMakeLists.txt`** — 三处改动：

```cmake
set(VALID_MODELS CS96-alpha CS96-beta CS96-gamma MF150-fl6031 MF150-fl6532)

elseif(MODEL STREQUAL "CS96-gamma")
    message(STATUS "Detected CS96-gamma model")
    add_compile_definitions(CS96_GAMMA=1)
    set(DRIVER_SUBMODULE_BRANCH am6204)
    set(CC_SUBMODULE_BRANCH aarch64-buildroot-linux-gnu)
```

以及第 182-194 行的**源文件排除正则**（CMake 是硬编码正则，与 Makefile 的自动派生不同）：

```cmake
elseif(MODEL STREQUAL "CS96-gamma")
    list(FILTER C_SOURCES EXCLUDE REGEX "consumer/models/ys_consumer_model_(mf150|cs96_alpha|cs96_beta)")
    list(FILTER C_SOURCES EXCLUDE REGEX "producer/.*_(mf150|cs96_alpha|cs96_beta)")
    list(FILTER C_SOURCES EXCLUDE REGEX "decode/ys_decode_(mf150|cs96_alpha|cs96_beta)")
```

同时需把 `cs96_gamma` 加入其余 3 个既有分支的排除正则，否则链接期重复符号。

**③ `aarch64-toolchain.cmake`** — 该文件自带一份机型校验表，需同步，否则编译器探测阶段直接 `FATAL_ERROR`。

### 4.2 驱动库构建

**驱动子模块侧**（需驱动团队配合，改动很小）：

```makefile
# driver/src/Makefile
CROSS_COMPILE ?=
DEF_RCV_MODE  ?= 1
COMPILER := $(CROSS_COMPILE)aarch64-buildroot-linux-gnu-gcc

all: version
	$(COMPILER) -Wall -std=gnu99 -I ./ -DDEF_RCV_MODE=$(DEF_RCV_MODE) \
		yousee_lidar_api.c -o liblidar.so -shared -fPIC
```

```c
/* driver/src/yousee_lidar_api.h */
#ifndef DEF_RCV_MODE          /* 新增保护，允许命令行 -D 覆盖 */
#define DEF_RCV_MODE 1
#endif
```

**主仓侧**（`Makefile`）：

```makefile
DRIVER_RCV_MODE := $(word 6,$(subst :, ,$(MODEL_CFG)))
DRIVER_LIB      := lib/$(MODEL)/liblidar.so
DRIVER_SRCS     := $(wildcard driver/src/*.c) $(wildcard driver/src/*.h)

# 驱动库：从 driver 子模块源码按机型的通道模式编译
$(DRIVER_LIB): $(DRIVER_SRCS)
	$(MAKE) -C driver/src CROSS_COMPILE=$(CURDIR)/cc/bin/ DEF_RCV_MODE=$(DRIVER_RCV_MODE)
	@mkdir -p $(dir $@)
	cp driver/src/liblidar.so $@

build_only: you_see
```

首次构建或驱动源码变更时自动重编；其他机型沿用已入库的预编译库（`lib/CS96-alpha`、`lib/CS96-beta` 保持不变，避免受驱动源码接口演进影响）。

**注意事项**：

- `driver/src/yousee_lidar_api.c` 中 `spad_spi_*`、`sys_workmode_*`、电机/VCSEL/温度类接口为空实现（`return 0`），这是**当前架构的既定状态**——SPAD 由 FPGA 管理，ARM 端不再直接操作。gamma 不需要这些接口，不影响功能。
- 驱动源码编译依赖 `driver/src/yousee_lidar_ver.h`（由 `gen_version.sh` 生成），Makefile 的 `version` 前置目标已处理。
- `lib/CS96-gamma/libdbus.a`、`libuv.a` 与 beta 同平台（aarch64-buildroot-linux-gnu），直接从 `lib/CS96-beta/` 复制即可。
- 产物 `.so` 在 `.gitignore` 中被忽略；现有 `lib/*/liblidar.so` 是 `git add -f` 强制入库的。新机型的库建议**不入库**，由构建产出。

## 5. 关键模块设计

### 5.1 数据包结构（`core/ys_core_def.h`）

新增 `#elif CS96_GAMMA == 1` 分支：

```c
#elif CS96_GAMMA == 1
typedef struct {
	uint8_t header[16]; // 包头：slot_num[11:0] + mirror_angle[31:12] + 相对时间[55:32]us
			    //      + 保留[111:56] + frame_id[119:112] + 保留[127:120]
	uint8_t value[1];
} org_point_cloud_packet_t;

/* 与 beta 完全一致的三项，逻辑可原样复用 */
static inline uint16_t cs96_gamma_get_slot_number(org_point_cloud_packet_t *p)
{
	return ((uint16_t)p->header[1] << 8 | p->header[0]) & 0x0FFF;
}

static inline uint32_t cs96_gamma_get_mirror_angle(org_point_cloud_packet_t *p)
{
	uint32_t v = (uint32_t)p->header[3] << 24 | (uint32_t)p->header[2] << 16 |
		     (uint32_t)p->header[1] << 8 | (uint32_t)p->header[0];
	return (v >> 12) & 0xFFFFF;
}

static inline uint8_t cs96_gamma_get_fpga_frame_id(org_point_cloud_packet_t *p)
{
	return p->header[14];
}

/* 差异点：24 位 µs 相对时间（低字节在前） */
static inline uint32_t cs96_gamma_get_relative_time(org_point_cloud_packet_t *p)
{
	return (uint32_t)p->header[6] << 16 | (uint32_t)p->header[5] << 8 | (uint32_t)p->header[4];
}
#endif
```

### 5.2 协议头构建（`ys_business/algo/ys_algo_build_protocal_head.c`）

新增 `#elif CS96_GAMMA == 1` 分支，与 beta 的差异仅在时间字段：

```c
#elif CS96_GAMMA == 1
int build_protocal_head(raw_protocal_data_packet_t *raw_data, point_cloud_head_t *p_head)
{
	...
	p_head->total_slots    = total_slots;
	p_head->slot_number    = cs96_gamma_get_slot_number(org_data);
	p_head->echo_mode      = (uint8_t)(config.echo_mode);
	p_head->coordinate_mode = (uint8_t)(config.coordinate_mode);

	/* 24 位 µs 相对时间 → 协议 delay[10] 字段（字节序按上位机协议确认） */
	memset(p_head->delay, 0, sizeof(p_head->delay));
	uint32_t rel_us = cs96_gamma_get_relative_time(org_data);
	memcpy(p_head->delay, &rel_us, 3);

	p_head->frame_index = cs96_gamma_get_fpga_frame_id(org_data) % 4;
	return sizeof(point_cloud_head_t);
}
#endif
```

> ⚠️ `delay[10]` 字段的填充方式决定上位机能否正确解析时间戳，见 §7 待确认事项。

### 5.3 解码层（`ys_decode_cs96_gamma.c`）

复制 `ys_decode_cs96_beta.c` 并改名，四个接口函数中：

| 函数 | 处理 |
|---|---|
| `decode_calculate_theta()` | 原样复用 |
| `decode_init_model_encoder()` | 原样复用（gamma 的 `angle_face`/`side_angular_offset` 语义与 beta 相同） |
| `decode_build_protocal_head()` | 转调 §5.2 的新分支 |
| `decode_get_horizontal_corners()` | 原样复用（转镜机制相同） |
| `orgin_point_cloud_data_is_valid()` | 原样复用（`side_light` 面使能过滤） |

日志中的 `[CS96_Beta]` 前缀改为 `[CS96_Gamma]`。

真正的点云解析主循环在共享文件 `ys_decode_common.c` 中（`deal_orgin_point_cloud_data`），**零改动**。

### 5.4 生产者（`ys_producer_point_cloud_cs96_gamma.c`）

复制 beta 版本，改动点：

- `LOCAL_TEST` 回放路径：`./file/CS96-gamma/point_cloud_data`
- 头文件 include guard 与函数签名保持一致

数据搬运逻辑（按 `org_point_cloud_slot_size` 步进、`slot_number==0` 判帧边界、`sleep_slot` 休眠）**无需修改**——`org_point_cloud_slot_size` 会由 `lines_v=120` 自动算出 1936。

`ys_business/ys_producer.c` 的 include 列表补一行：

```c
#include "producer/point_cloud/ys_producer_point_cloud_cs96_gamma.h"
```

### 5.5 消费者模型（`ys_consumer_model_cs96_gamma.c`）

复制 beta 版本，四个接口全部转调共享实现，**无逻辑差异**：

- `consumer_model_get_processed_len()` → 复用
- `consumer_model_point_cloud_is_valid()` → `orgin_point_cloud_data_is_valid()`
- `consumer_model_transform_point_cloud()` → `inverted_orgin_point_cloud_data()`
- `consumer_model_parse_point_cloud()` → `deal_orgin_point_cloud_data()`

### 5.6 SPAD 初始化

gamma **不需要 ARM 端初始化**，`core/ys_core_spad.c` 只需：

```c
#elif CS96_GAMMA == 1
int spad_init(int work_mode)
{
	(void)work_mode;
	return RET_OK;   /* SL100 由 FPGA 自动初始化，ARM 端不参与 */
}
#endif
```

`core/ys_core_system.c` 的 `sys_spad_init()` 中 gamma 走 `spad_init(work_mode)` 分支（与 beta 同形），因立即返回 `RET_OK` 而不会超时。

实机上 `conf/ys_conf.ini` 的 `set_spad` 默认即为 `0`（不配置），该分支实际不会被触发，保留仅为接口完整性。


新增 `conf/ys_calibration_gamma.ini`，基于 beta 版本修改：

`[side_angular_offset]`、`[standard_encoder]`、`[horizontal_angular_offset]`、`[distance_factor]` 等需标定流程产出，本地文件先填占位值。

## 8. 实施步骤

按依赖顺序，建议分 5 步提交：

**第 1 步：构建系统接入**（可独立验证）
1. `driver/src/Makefile` + `yousee_lidar_api.h` 支持 `DEF_RCV_MODE` 参数
2. 主仓 `Makefile`、`CMakeLists.txt`、`aarch64-toolchain.cmake` 注册 `CS96-gamma`
3. 准备 `lib/CS96-gamma/`（复制 `libdbus.a`、`libuv.a`）
4. 验证：`make MODEL=CS96-gamma` 能编译通过（此时用 beta 的源文件占位）

**第 2 步：驱动库产出**

## 9. 风险与规避

| 风险 | 规避措施 |
|---|---|
| CMake 的源文件排除正则是硬编码的，漏改会重复符号 | 第 1 步编译验证时即暴露；建议顺手改为从机型表派生 |
| 驱动源码接口在演进（`hist_one_*`、`version_date_get` 已被删除），业务层仍在隐式调用 | gamma 代码只调用 `yousee_lidar_api_public.h` 中已声明的接口，不使用隐式符号 |
| `get_encoder()` 读 0x2048/0x204C，与 `calib_light_enb3/4` 写同址（读写语义复用） | 沿用 beta 现有实现；如实机出现编码器数据异常，优先排查此处 |
| 其他机型受驱动源码变更影响 | 仅 gamma 走构建时编译驱动；alpha/beta/MF150 继续使用已入库的预编译库 |
